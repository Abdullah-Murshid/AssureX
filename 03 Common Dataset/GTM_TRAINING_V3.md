# GTM retraining — dataset v3

## 1. What to upload

Create a **new** Google Teachable Machine **Image Project → Standard image model**.
Use exactly these three class names:

- `Valid Claim`
- `Invalid Claim`
- `Manual Review`

Upload **only** the training cards:

| Class | Folder | Files |
|---|---|---:|
| Valid Claim | `03 Common Dataset/summary_cards_v3/train/Valid Claim/` | 700 |
| Invalid Claim | `03 Common Dataset/summary_cards_v3/train/Invalid Claim/` | 700 |
| Manual Review | `03 Common Dataset/summary_cards_v3/train/Manual Review/` | 700 |

**Do not upload** `val/` or `test/`. They are the held-out evaluation sets.

The cards are 600×600, variation 1 (light) and variation 2 (dark), generated by the same
`render_claim_card()` function the web app uses. Every card shows claim facts only — no
Python prediction, confidence, final decision, or class label.

## 2. Suggested training settings

Record exactly what you use in the GTM evidence folder.

- Epochs: 50–100
- Batch size: 16 or 32
- Learning rate: default (0.001)
- Augmentation: only mild, label-preserving changes if the UI offers it
- Keep the three classes balanced (700/700/700)

If the preview looks unstable, increase epochs before changing the dataset. Do not add
validation/test cards to fix errors.

## 3. Export

Export **TensorFlow → Keras** and keep both files together:

- `keras_model.h5`
- `labels.txt` (must stay in exported order)

Replace:

```
GTM Models/keras_model.h5
GTM Models/labels.txt
```

The application sets `TF_USE_LEGACY_KERAS=1` automatically, so the Keras 2 H5 loads under
TensorFlow 2.21 + `tf-keras`.

## 4. Evaluate

From `02 Source Repository`:

```powershell
uv run python dataset_generator/evaluate_gtm_v3.py
```

The harness reports:

- 225 held-out v3 test cards (accuracy, per-class P/R/F1, confusion matrix)
- 30 cards rendered by the live application renderer
- predicted-class distribution and misclassified examples

Reports are written to
`05 Teachable Machine Evidence/v3_evaluation.json`.

## 5. Acceptance gates

| Gate | Required |
|---|---:|
| v3 test accuracy | **≥ 85%** |
| live-render accuracy (30 cards) | **≥ 85%** |
| Manual Review recall | **≥ 70%** |
| Valid Claim recall | **> 0** (the old model is 0/75) |
| Predicted distribution | not ~100% one class |

Current baseline: the old model scores **33.3%** on v3 and predicts **Invalid Claim for all
225** test cards. Any new model must beat this clearly.

## 6. If the gate fails

Iterate on the **data/card design**, not the test set:

- Add 2–4 more label-preserving variations per training claim (font size, spacing,
  background, compression).
- Reduce the number of fields or increase the value font further; the GTM input is
  224×224, so small text is the limiting factor.
- Consider large status chips for warranty state, missing documents, serial match,
  repairs, and contradiction — these are claim facts, not the label.
- Re-render train/val/test together so the distributions stay identical.

Do not move failed test cards into training. Do not tune thresholds on the test set.

## 7. Evidence to capture

- GTM project link
- Screenshots of the three classes and image counts
- Training settings (epochs, batch size, learning rate)
- Training observations and any retraining history
- Exported model hash and version label (e.g. `gtm-v3-2026-10-22`)
- Test and live-render reports
- Sample Claim Summary Cards (v3)
